# Техническое задание: Mac AI Mode

## 1. Цель

Создать управляемый режим `AI Mode` для MacBook Pro M1 Max с 64 GB unified memory под macOS.

При активации режима компьютер должен освобождать максимум доступных ресурсов для локального LLM inference, при этом сохранять управление через SSH и доступ к AI API по локальной сети.

Режим должен быть обратимым, запускаться вручную или удалённо и не требовать перезагрузки компьютера.

## 2. Окружение

- MacBook Pro с Apple M1 Max, 64 GB RAM.
- macOS, версия определяется при установке.
- Внешний Ethernet через USB-адаптер.
- Док-станция и внешний монитор.
- Возможна работа с закрытой крышкой ноутбука.
- Основной удалённый клиент — другой Mac, M4 Pro с 48 GB RAM.
- Дополнительное управление — с телефона по локальной сети.
- Компьютер может выполнять долгие автономные задачи, в том числе ночью.

Перед установкой провести аудит текущего окружения: установленного ПО, автозагрузки, служб, энергосбережения, доступного дискового пространства и сетевой конфигурации.

## 3. Архитектура

Реализовать три основных компонента:

### A. AI Mode Manager

Локальная CLI-утилита для управления режимами.

Предусмотреть команды:

```bash
aimode on
aimode off
aimode status
aimode doctor
aimode logs
aimode models
aimode switch <model>
```

`on` — освобождает ресурсы и запускает AI-сервер.

`off` — останавливает AI-сервер и возвращает изменённые настройки, возобновляет ранее работающие управляемые службы.

`status` — показывает текущий режим, модель, использование памяти, нагрузку и доступность API.

`doctor` — диагностика зависимостей, сети, Metal, разрешений и условий работы с закрытой крышкой.

`models` — показывает установленные модели.

`switch` — меняет активную модель без перезагрузки macOS.

### B. LLM Runtime

Первоначальный backend — `llama.cpp` с поддержкой Metal.

Требования:

- Использование GPU через Metal.
- Работа с GGUF-моделями.
- OpenAI-compatible API.
- Настраиваемый контекст.
- Управление количеством параллельных запросов.
- Выбор модели через конфигурацию.
- Настраиваемые параметры выделения памяти.
- Возможность выгрузить текущую модель и загрузить другую.
- Логирование ошибок и времени загрузки.
- Возможность замены backend в будущем, например на Ollama.

Начать с одной загруженной модели и одного inference-сервера. Не запускать несколько моделей одновременно без явной настройки.

Предусмотреть отдельные профили моделей:

- `fast` — небольшая модель для быстрых ответов.
- `coding` — модель для программирования и агентных задач.
- `large` — максимально крупная практически применимая модель для 64 GB.

Конкретные модели выбрать после проверки актуальных вариантов, совместимости, потребления памяти и производительности.

### C. Remote Controller

Предоставить возможность управления режимом по сети.

Основной способ — SSH:

```bash
ssh ai-mac aimode on
ssh ai-mac aimode off
ssh ai-mac aimode status
ssh ai-mac aimode switch coding
```

Также предусмотреть небольшой HTTP management API, если он не усложнит архитектуру.

Возможные endpoints:

```text
GET  /status
GET  /models
POST /mode/on
POST /mode/off
POST /models/activate
GET  /health
```

Управляющий API должен иметь аутентификацию, работать только в доверенной сети или через защищённый туннель и не предоставлять произвольное выполнение shell-команд.

Inference API должен быть доступен другим устройствам в локальной сети. Не публиковать его напрямую в интернет.

## 4. Управление ресурсами

Это основная часть проекта.

При входе в AI Mode:

1. Сохранить состояние управляемых пользовательских процессов и служб.
2. Проверить наличие активных пользовательских задач и предупредить о возможной потере несохранённых данных.
3. Корректно завершить выбранные приложения, освобождая оперативную память.
4. Остановить явно разрешённые фоновые службы.
5. Отключить явно разрешённые фоновые задания и ненужные автозапуски на время режима.
6. Не допустить автоматического повторного запуска остановленных управляемых служб.
7. Проверить доступную память и memory pressure.
8. Запустить LLM runtime.
9. Загрузить выбранную модель.
10. Убедиться, что API отвечает.

Примеры кандидатов на остановку:

- Браузеры и их вспомогательные процессы.
- IDE и редакторы.
- Docker и виртуальные машины.
- Пользовательские серверы разработки.
- Пользовательские синхронизаторы.
- Другие ресурсоёмкие приложения и пользовательские фоновые задачи.

Фактический список формировать по результатам аудита. Реализовать allowlist/denylist и режим предварительного просмотра действий.

Не останавливать:

- SSH и сетевые службы, необходимые для управления.
- Системные компоненты macOS.
- WindowServer и критические службы графической подсистемы.
- Службы питания и управления устройствами.
- Необходимые компоненты Metal.
- Другие процессы, остановка которых может нарушить стабильность macOS.

Не использовать массовое завершение процессов, отключение SIP и изменение защищённых системных компонентов.

Не считать очищение файлового кэша обязательной оптимизацией. Основные показатели — memory pressure, swap activity, реально доступная память и скорость inference.

Режим `off` должен восстанавливать состояние управляемых служб и настройки, но не обязан автоматически открывать все ранее закрытые GUI-приложения.

## 5. Работа без экрана и с закрытой крышкой

Необходимо обеспечить продолжительную автономную работу.

Проверить:

- Power Nap и Wake for Network Access, если соответствующие параметры поддерживаются системой.
- Возможность использования `caffeinate` для предотвращения обычного сна.
- Поведение системы при закрытии крышки.
- Работу внешнего Ethernet после перехода в соответствующий режим.
- Условия работы в clamshell mode с внешним питанием и монитором.
- Возможность удалённого пробуждения по сети.
- Поведение после временной потери питания или сетевого соединения.

Не считать, что `caffeinate` гарантирует работу с закрытой крышкой. Проверить это экспериментально.

Для машины, оставленной в AI Mode, предусмотреть механизм предотвращения нежелательного сна, если он поддерживается данной конфигурацией.

## 6. Запуск и жизненный цикл

Использовать `launchd` для управления постоянно доступными компонентами.

После обычной загрузки macOS:

- AI Mode по умолчанию выключен.
- Лёгкий управляющий компонент доступен.
- Тяжёлая LLM не загружается автоматически.
- По SSH можно активировать режим.

При переключении в AI Mode:

```text
NORMAL
  |
  v
PREPARING
  |
  v
RELEASING RESOURCES
  |
  v
STARTING LLM
  |
  v
AI READY
```

Если запуск не удался, вернуть конфигурацию в безопасное состояние и сообщить причину.

Предусмотреть идемпотентность команд, обработку сигналов, защиту от одновременных переключений и журнал переходов.

Если AI-сервер аварийно завершается, предусмотреть ограниченный перезапуск с защитой от бесконечного цикла ошибок.

## 7. Мониторинг

Команда `aimode status` должна показывать:

```text
Mode:       AI READY
Model:      <active model>
Backend:    llama.cpp / Metal
RAM:        <used / total>
Pressure:   <memory pressure>
Swap:       <used and activity>
CPU:        <usage>
GPU:        <available telemetry>
API:        <host:port>
Uptime:     <runtime uptime>
```

Отображать только метрики, которые действительно доступны на macOS, без вымышленных показателей использования GPU.

Добавить простой benchmark:

- Время загрузки модели.
- Prompt processing tokens/sec.
- Generation tokens/sec.
- Пиковое использование памяти.
- Memory pressure и swap activity.
- Результаты при разных размерах контекста.

Сохранять результаты в машиночитаемом формате, например JSON.

## 8. Интеграция с агентами

Локальный LLM должен быть доступен извне через OpenAI-compatible API.

Предусмотреть использование с:

- CLI-агентами.
- Редакторами кода.
- Собственными Python/PHP-скриптами.
- Браузерными агентами.
- Open WebUI или аналогичным интерфейсом в качестве необязательного дополнения.

Система должна позволять отправить задачу с другого компьютера, закрыть клиент и продолжить её выполнение на сервере, если используется соответствующий долгоживущий агент.

При этом отдельно разграничить обязанности inference-сервера и исполнительного агента. Сам LLM-сервер не обязан хранить состояние задач, управлять браузером или исполнять команды.

На первом этапе реализовать стабильный inference API. Браузерный агент и очередь автономных задач — последующий этап.

## 9. Безопасность и восстановление

Обязательные требования:

- Не терять доступ по SSH при переключении режимов.
- Не использовать необратимые настройки.
- Не удалять пользовательские данные.
- Не отключать системную безопасность macOS.
- Не завершать приложения с несохранёнными данными без подтверждения или заранее разрешённой политики.
- Создать механизм отката при неудачном включении.
- Сохранять журнал действий.
- Поддерживать `--dry-run`.
- Повторный вызов `on` или `off` не должен приводить к ошибкам состояния.

Наличие доступного SSH должно проверяться до остановки служб, если активация производится удалённо.

## 10. План реализации

### Этап 1. Аудит

Собрать характеристики машины, версию macOS, сведения о памяти, активных службах, автозагрузке, питании и сети.

Сформировать список безопасных оптимизаций.

Ничего не отключать на этом этапе.

### Этап 2. LLM Runtime

Установить llama.cpp, настроить Metal, загрузить тестовую модель и запустить OpenAI-compatible API.

Проверить запросы с локальной машины и с Mac M4 Pro.

### Этап 3. AI Mode Manager

Реализовать CLI, управление процессами, конфигурацию, сохранение состояния и обратимое переключение режимов.

### Этап 4. Удалённое управление

Настроить SSH-вызовы и при необходимости небольшой защищённый management API.

### Этап 5. Энергопитание

Проверить работу в доке, с закрытой крышкой, по Ethernet, пробуждение по сети и длительную работу без взаимодействия.

### Этап 6. Оптимизация

Измерить расход памяти macOS в обычном и AI-режимах.

Проверить несколько моделей и определить практические пределы для 64 GB RAM.

### Этап 7. Автономные агенты

Подготовить независимый слой для выполнения долгих задач, использования браузера и хранения результатов.

## 12. Критерии готовности

Проект считается готовым, когда:

1. AI Mode включается локально одной командой.
2. AI Mode включается по SSH с другого Mac.
3. Управляемые фоновые приложения и службы освобождают память.
4. LLM запускается с Metal.
5. API доступен удалённо.
6. Модель можно сменить командой.
7. Состояние системы и потребление ресурсов доступны через CLI.
8. Компьютер выдерживает длительный тест без самопроизвольного сна.
9. `aimode off` корректно возвращает систему в обычный режим.
10. Потеря соединения во время переключения не оставляет систему без управления.

## 13. Порядок работы coding-агента

Работать итеративно.

Сначала выполнить аудит и подготовить план изменений на основе фактической конфигурации машины.

Затем создать проект, реализовать минимальную работоспособную версию и проверить её.

Не выполнять потенциально разрушительные системные операции автоматически.

Перед изменениями в автозагрузке, системных службах, настройках питания или удалённом доступе показывать точный список планируемых действий.

После каждой стадии выполнять проверку работоспособности и фиксировать результат.

Приоритеты:

1. Стабильность и сохранение удалённого доступа.
2. Максимальное выделение доступной памяти для LLM.
3. Обратимость переключения.
4. Удобство управления.
5. Производительность inference.
6. Дополнительные интерфейсы и функции.
